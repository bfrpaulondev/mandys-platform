# Mandy's V0.1 operations checkpoint

This checkpoint records the operational baseline now required for internal QA and an unpaid pilot restaurant.

## Operational surface

- authenticated, role-aware Backoffice navigation;
- international restaurant/location onboarding;
- owner/manager profile and operational settings;
- opening hours for all seven weekdays;
- dining areas and restaurant tables;
- menu, reservations, CRM, events, takeaway orders, stock and Insights;
- in-app notifications, audit/activity, team management and data protection;
- plan/subscription screen with commercial charging kept fail-closed.

## Runtime and isolation

Private requests resolve the Mandy's Better Auth session and active organization on the server. Business transactions set `app.organization_id` transaction-locally, while PostgreSQL RLS remains defense in depth. Client-supplied tenant identifiers do not select the tenant.

The release suite exercises disposable authenticated tenants, cross-tenant spoofing attempts and role-specific access. The operational role matrix is also frozen by CI guards so runtime allowlists cannot silently drift from Better Auth declarations.

## Release gates

A main-branch release must pass:

1. lint, strict TypeScript, Edge-function contract/security guards, pricing guardrails, unit tests, build and dependency audit;
2. versioned Netlify live-readiness for Storefront and Backoffice;
3. health checks for critical Edge runtimes and pre-launch Stripe/email safety switches;
4. Chromium E2E for the public Storefront, authenticated owner lifecycle, billing fail-closed, cross-tenant isolation and operational roles.

The earlier 'final V0.1 gate remains browser E2E' item is therefore complete once the current release suite is green.
