# Module map

| Module | Current state | Purpose |
|---|---:|---|
| Core | Shipped | Tenant, users, locations, settings, themes, permissions, notifications and audit |
| Menu | Shipped | Menus, categories, items, translations, allergens and publication |
| Reservations | Shipped | Areas, tables, availability, policies, exceptions, reservations and waitlist |
| Events | Shipped | Group and private-event enquiry pipeline |
| CRM | Shipped foundation | Customer directory, contact details, consent and operational history |
| Orders | Shipped foundation | Direct takeaway ordering, public tracking and kitchen status flow; online card payment remains later |
| Stock | Shipped foundation | Ingredients, recipes, suppliers, movements, average cost and low-stock monitoring |
| Analytics | Shipped foundation | Operational and commercial Insights across current restaurant data |
| Loyalty | Later | Repeat-customer programmes and offers |
| Multi-location | Later | Group-level permissions and consolidated operations |
| AI | Later | Provider-neutral assistant over authorized restaurant data |

A module entitlement controls commercial access. Themes use a separate entitlement model so presentation can be sold independently of business capabilities. SaaS plan records map commercial plans to module sets, but plan pricing and provider checkout remain private until explicitly approved for launch.
